Clear answers

Built to be questioned.

Is the console showing a mock run?

No. It reads an explicitly public, allowlisted projection of Rally’s authoritative runner state from Cloudflare D1. If that service fails, the page shows the failure instead of sample data.

Are two agents just agreeing with each other?

No. They execute separately, come from different model families, and cannot verify checklist work they own.

Do the agents wait for each other?

Yes. Rally runs one model at a time, waits for its turn to finish, validates and saves the accepted state, and only then dispatches the other model. A timeout or failed process stops the run instead of handing over partial state.

Do emails literally trigger every model turn?

The first email starts the real run and every turn is mirrored to the thread. The authoritative runner dispatches the next model locally.

What happens when the agents cannot finish?

Rally stops with a precise halt report when work is blocked, repeatedly rejected, stalled, timed out, or over budget.

Is Rally an official Google product?

No. Rally is an independent Agent9 project built with Gemini, Google ADK, and Google Cloud for the All Things Agentic Hackathon.

What stays private?

Commissioner identity, worktree paths, mail IDs, raw prompts, credentials, and cloud request keys never enter the public console record.

What does “give Rally a job” mean?

Start with one bounded outcome Rally can own repeatedly—such as repository maintenance or release preparation—then grant only the access, limits, and approval rules that outcome needs.

Are the business connectors live?

Not yet. The current build proves email intake, repository execution, Google governance, and public evidence. Cloudflare, n8n, Workspace, and GitHub are the researched connector sequence, clearly labeled as roadmap.
